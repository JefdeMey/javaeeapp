──────────────────────────────────────────────────────────────────────────────
LESONDERDEEL 1: INTRO IN JEE — SERVLETS EN EJB'S, DEPLOYMENT OP WILDFLY
──────────────────────────────────────────────────────────────────────────────

WAT IS HET?
  Java EE (nu Jakarta EE) is een set standaarden voor enterprise Java.
  - Servlet: een Java-klasse die HTTP-verzoeken afhandelt (basis van elke
    webapplicatie in Java).
  - EJB (Enterprise JavaBean): beheerde server-side componenten voor
    transactie-, concurrency- en beveiligingsbeheer.
  - WildFly: een open-source Jakarta EE-applicatieserver die deze componenten
    host (concurrent met Tomcat maar vollediger).

HOE GEBRUIKT IN DE APP?
  De app is verpakt als WAR (Web Application Archive) en is bedoeld voor
  deployment op WildFly. SpringBootServletInitializer overschrijft de
  traditionele EJB-aanpak: Spring beheert de beans zelf, maar de
  WAR-verpakking is pure Java EE-conventie.

  Relevante bestanden:
    src/main/java/be/ucll/SpringMain.java
      → extends SpringBootServletInitializer (registreert de app als servlet)
      → implements AppShellConfigurator (Vaadin-integratiehaak)
    pom.xml
      → <packaging>war</packaging>
      → jakarta.ee-api als provided-dependency (WildFly levert de API)
    src/main/java/be/ucll/spring/JpaConfig.java
      → @Primary op TransactionManager: overschrijft WildFly's eigen
        transactiemanager zodat Spring er controle over heeft.

WAAROM ZO?
  WildFly heeft een eigen JTA-transactiemanager. Door @Primary te zetten
  op de Spring JpaTransactionManager, voorkom je conflicten bij deployment
  op WildFly en houd je volledige Spring-controle over transacties.

LESONDERDEEL 2: VAADIN EN JAVA EE / VAADIN EN SPRING BOOT
──────────────────────────────────────────────────────────────────────────────

WAT IS HET?
  Vaadin is een server-side UI-framework voor Java. De UI-logica draait op
  de server; de browser toont alleen het resultaat via een automatisch
  gegenereerde web-component-laag. Geen REST-endpoints of JavaScript nodig
  voor de basiswerking.

  Kernconcepten:
  - @Route:          koppelt een Java-klasse aan een URL-pad
  - RouterLayout:    template-klasse die alle views insluit
  - HasUrlParameter: view die een parameter ontvangt via de URL
  - BeforeEnterObserver: hook die uitgevoerd wordt vóór een view geladen wordt
  - VaadinSession:   sessie-opslag per gebruiker (serverside)

HOE GEBRUIKT IN DE APP?

  Routing en template:
    MainLayout.java     → RouterLayout; bevat Header, routerslot en Footer
    LoginView.java      → @Route(value = "", layout = MainLayout.class)
    ZoekView.java       → @Route(value = "zoek", layout = MainLayout.class)
    DetailView.java     → @Route(value = "detail", layout = MainLayout.class)
                          + HasUrlParameter<Long> → ontvangt bestel-ID in URL
                          + BeforeEnterObserver   → redirect als niet ingelogd

  Authenticatie-guard (BeforeEnterObserver):
    ZoekView.java / DetailView.java:
      public void beforeEnter(BeforeEnterEvent event) {
          if (!SessionBeheer.isIngelogd()) {
              event.forwardTo(LoginView.class);
          }
      }

  Sessie:
    SessionBeheer.java → VaadinSession.getCurrent().setAttribute(...)
    Alle views lezen de ingelogde gebruiker via SessionBeheer.getGebruiker()

  UI-componenten gebruikt in de app:
    TextField, PasswordField, BigDecimalField, IntegerField — invoer
    ComboBox<String>     — autocomplete voor productnamen
    Checkbox             — afgeleverd-filter
    Grid<Bestelling>     — zoekresultaten
    Grid<BestellingRegel>— productendetail
    Button               — acties (zoeken, wissen, detail, terug, email, logout)
    VerticalLayout, HorizontalLayout, FormLayout — responsieve containers

  Spring-integratie:
    @Autowired in views: Vaadin detecteert Spring en gebruikt de
    Spring-toepassingscontext als dependency-injection-provider.
    Geen extra configuratie nodig: Vaadin-Spring-starter regelt dit.

WAAROM VAADIN?
  Java-first: geen HTML/JS nodig voor de UI. De layout past zich automatisch
  aan de viewport aan via VerticalLayout/HorizontalLayout/FormLayout.

LESONDERDEEL 4: ASYNCHRONE COMMUNICATIE
            (Spring polling/scheduling, JMS, bestandsintegratie)
──────────────────────────────────────────────────────────────────────────────

WAT IS HET?
  - JMS (Java Message Service): standaard API voor berichtenuitwisseling.
    Berichten gaan via een broker (hier: ActiveMQ) naar een queue of topic.
    Producer en consumer werken onafhankelijk van elkaar.
  - Queue: point-to-point, één consumer per bericht.
  - Topic: publish-subscribe, alle subscribers ontvangen het bericht.
  - @JmsListener: Spring-annotatie die een methode als consumerhandler aanduidt.
  - JmsTemplate: Spring-hulpklasse voor het versturen van JMS-berichten.

HOE GEBRUIKT IN DE APP?

  Configuratie (embedded broker):
    src/main/java/be/ucll/spring/JmsConfig.java
      @Bean BrokerService activeMQBroker()
        → start een in-process ActiveMQ-broker op tcp://localhost:61616
      @Bean ActiveMQConnectionFactory
        → verbinding met username "admin"
      @Bean JmsTemplate
        → gebruikt MappingJackson2MessageConverter (berichten als JSON)
      @Bean DefaultJmsListenerContainerFactory
        → 1 tot 3 gelijktijdige listener-threads

  Queue aanmaken:
    @Bean ActiveMQQueue zoekResultaatQueue()
      → naam: "zoek.resultaat.queue"

  Berichtklassen (Serializable):
    src/main/java/be/ucll/jms/ZoekResultaatBericht.java
      Velden: List<Long> bestellingIds, String emailAdres, String gebruikerNaam

  Producer (versturen):
    src/main/java/be/ucll/jms/BestellingProducer.java
      jmsTemplate.convertAndSend("zoek.resultaat.queue", bericht)
    Wordt aangeroepen vanuit ZoekView bij klik op "Stuur Email"-knop.
    → De UI-thread keert ONMIDDELLIJK terug; de gebruiker kan gewoon
      verder werken.

  Consumer (verwerken):
    src/main/java/be/ucll/jms/BestellingStatusListener.java
      @JmsListener(destination = "zoek.resultaat.queue")
      public void verwerkZoekResultaat(ZoekResultaatBericht bericht) { ... }
    Haalt Bestelling-objecten op uit DB, roept MailService.stuurZoekResultaat()
    aan. Draait in een aparte thread, volledig asynchroon.

  Stroomdiagram:
    [ZoekView - knop] → BestellingProducer.verstuurZoekResultaat()
        → ActiveMQ queue "zoek.resultaat.queue"
            → BestellingStatusListener.verwerkZoekResultaat()
                → BestellingService.findById() per ID
                    → MailServiceImpl.stuurZoekResultaat()
                        → Gmail SMTP → email bij gebruiker

  Scheduling (niet gebruikt in app maar in cursus):
    @EnableScheduling + @Scheduled(fixedRate = 5000)
    → laat een methode periodiek uitvoeren (polling-patroon).

LESONDERDEEL 5: SPRING SECURITY / JWT
──────────────────────────────────────────────────────────────────────────────

WAT IS HET?
  - Spring Security: framework voor authenticatie en autorisatie in Spring.
  - JWT (JSON Web Token): compact, zelfstandig token dat claims bevat
    (gebruikersnaam, rollen, vervaltijd). Gesigneerd met een geheime sleutel.
  - Werking: na login geeft de server een JWT; de client stuurt dit mee in
    elke volgende request (Authorization: Bearer <token>).

HOE GEBRUIKT IN DE APP?
  De app gebruikt GEEN Spring Security of JWT. Authenticatie is
  handmatig geïmplementeerd:
    - GebruikerServiceImpl.login() vergelijkt gebruikersnaam + wachtwoord
    - SessionBeheer slaat de ingelogde gebruiker op in VaadinSession
    - BeforeEnterObserver in ZoekView en DetailView bewaakt toegang

  VOOR HET MONDELING — weet hoe je Spring Security zou toevoegen:
    1. Dependency: spring-boot-starter-security
    2. SecurityConfig (@EnableWebSecurity):
         http.authorizeHttpRequests(auth -> auth
             .requestMatchers("/login").permitAll()
             .anyRequest().authenticated())
    3. JWT-filter: leest Authorization-header, valideert token,
       zet SecurityContext
    4. Bij Vaadin: VaadinWebSecurity als basis voor de SecurityConfig

  Waarom JWT handig is tov sessies:
    Sessies vereisen server-side opslag (schaalbaarheid ↓).
    JWT is stateless: token bevat alle info, server hoeft niets op te slaan.
    Nadeel JWT: token ongeldig maken vóór vervaltijd is complex.

DEEL 4 — MOGELIJKE MONDELINGE VRAGEN
════════════════════════════════════════════════════════════════════════════════

Q: Waarom gebruik je JmsTemplate.convertAndSend() en niet een MessageCreator?
A: convertAndSend() combineert conversie (via de geconfigureerde
   MappingJackson2MessageConverter) en verzending in één stap. Een
   MessageCreator is lager-niveau en vereist handmatige conversie.

Q: Wat is het verschil tussen een JMS Queue en een Topic?
A: Queue = point-to-point, bericht gaat naar precies één consumer.
   Topic = publish-subscribe, elk geabonneerd component ontvangt het bericht.
   De app gebruikt een Queue: de e-mail mag maar één keer verstuurd worden.

Q: Waarom is de H2-databank via TCP geconfigureerd in plaats van embedded?
A: Via TCP kan de H2-console (of een externe tool) verbinden terwijl de app
   draait. Embedded H2 is exclusief voor de JVM die hem opent.
   Configuratie: JpaConfig.h2Server() + jdbc:h2:tcp://localhost/mem:db

Q: Waarom staat @Primary op de TransactionManager in JpaConfig?
A: WildFly biedt een JTA-transactiemanager aan via JNDI. Zonder @Primary
   zou Spring de WildFly-manager kiezen en verlies je controle over
   Spring-transacties (@Transactional werkt dan niet zoals verwacht).

Q: Wat is LOCK_MODE=0 in H2 en waarom?
A: LOCK_MODE=0 = READ_UNCOMMITTED: geen rij-locks. Nodig omdat de
   embedded ActiveMQ-broker en de JPA-laag soms gelijktijdig schrijven,
   wat anders tot deadlocks leidt in H2. Geconfigureerd via
   H2IsolationLevelInitializerBean.

Q: Hoe werkt de autocomplete in het productnaam-veld?
A: ComboBox<String> in ZoekView krijgt setItems() met alle productnamen
   uit de databank via ProductService.zoek(""). Bij typen filtert Vaadin
   client-side op de reeds geladen lijst.

Q: Wat is BeforeEnterObserver en waar gebruik je het?
A: Een Vaadin-interface met methode beforeEnter(BeforeEnterEvent).
   Wordt uitgevoerd vóór de view gerenderd wordt. In ZoekView en DetailView
   wordt gecontroleerd of de gebruiker ingelogd is; zo niet, forwardTo(Login).

Q: Wat is het verschil tussen @Transactional op service- vs. repository-niveau?
A: In de app staat @Transactional op de servicelaag. De repository-methodes
   zijn niet-transactioneel: ze erven de transactie van de service.
   Zo controleert de service de transactiegrens (commit/rollback).

Q: Hoe werkt JAXB?
A: JAXB (Jakarta XML Binding) mapt Java-objecten naar XML en terug.
   @XmlRootElement → klasse is een XML-root.
   @XmlElement → veld wordt XML-element.
   Marshaller.marshal() → Java → XML
   Unmarshaller.unmarshal() → XML → Java
   Vaak gegenereerd vanuit een XSD via mvn generate-sources.

Q: Wat is een JWT en hoe werkt het?
A: JSON Web Token = header.payload.signature (Base64url-encoded).
   Header: algoritme (bv. HS256).
   Payload: claims (sub, exp, roles…).
   Signature: HMAC van header+payload met geheime sleutel.
   Server valideert handtekening; geen sessie-opslag nodig.
